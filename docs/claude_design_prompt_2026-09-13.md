## プロダクト概要

「SavePoint」は、Google Apps Script（GAS）を業務で使っている非エンジニア企業向けの変更管理システムです。Git/GitHubの知識がなくても、ブラウザだけでGASの変更履歴確認・過去状態への復元（ロールバック）・セーブポイント作成・権限管理・監査ログ・台帳管理ができます。

**想定ユーザー**: 税理士法人・中小企業の管理部門・情報システム担当者など、GitやGitHubを扱えない、または扱いたくない非エンジニアの方。ITツールへの習熟度は高くない前提でデザインしてください。

## 重要：このプロダクト特有の設計思想（必ず反映すること）

- GASはエディタで保存した瞬間に本番へ即座に反映されるため、**「承認されるまで本番反映を止める」機能は存在しない**。人による承認・却下の画面やボタンは作らないこと
- 変更管理は「①自動検知が変更を記録するログ（受動的）」→「②セーブポイント作成時にAIが影響レビューを生成（参考情報）」という2段階のみ。人がひとつずつ変更を承認する操作画面は不要
- 「セーブポイント」＝過去のある時点のコード状態を指す名詞。「セーブする」＝それを記録する操作（Git の commit に近い）。この用語で統一する（「リリース」という語はユーザー向け画面では使わない）

## トーン・世界観

- 信頼感・堅実さを重視（会計・法務に近い業務で使われるため、派手さより「事故を起こさない安心感」を優先）
- ダーク配色の左サイドバー＋明るいコンテンツ領域という構成を基本方針として踏襲
- サイドバー: ダーク背景（#14161b程度）、白系の文字
- アクセントカラー: グリーン系（#23b26d程度）。プライマリアクション・成功表示に使用
- 警告色: 黄系（変更あり等）、エラー色: 赤系
- フォント: Inter等のヒューマニストサンセリフ＋日本語はゴシック系（Hiragino Sans / Yu Gothic等）
- 全体的にホワイトスペースを活かした、カード＋テーブルベースのシンプルな管理画面デザイン

## 画面構成（6画面・実装済みの機能に完全対応）

### 1. ダッシュボード（トップ画面）
- サマリーカード4枚: GAS Projects数／変更あり／変更なし／認証エラー数
- 「未セーブの変更」パネル: 検知済みだがまだセーブしていない変更があるプロジェクトの一覧（プロジェクト名・検知日時・変更量、「セーブ画面へ」ボタンのみ。承認/却下ボタンは無い）
- 登録済みGASプロジェクトのカード一覧（プロジェクト名・Script ID・状態バッジ[確認中/変更あり/変更なし/認証エラー]・最終セーブ日時、ボタンは「差分を見る」「変更を検知」「セーブ画面へ」の3つのみ。差分は展開表示）

### 2. 台帳（GASプロジェクトの管理画面）
- スタンドアロンGAS自動検出セクション（検出実行ボタン→検出結果リスト→ワンクリック登録）
- バインドGAS向け手動登録フォーム（Project Name/Script ID/Google Account/用途/担当部署/ステータス）
- プロジェクト一覧テーブル（Project Name/Script ID/用途/担当部署/ステータス/README（AI生成、展開表示）/メンバー管理（展開でメンバー一覧・追加・削除、ロールはowner/maintainer/developer/viewerの4段階）/編集ボタン）
- 各行はインライン編集可能（編集→保存/キャンセル）

### 3. セーブ管理（5画面構成）
1. **プロジェクト選択**: 対象GASプロジェクトを選ぶ入口画面
2. **新規セーブ**: 未セーブの変更件数・変更量のサマリー、セーブコメント入力欄、「セーブすると前回セーブポイントからの変更内容についてAIが影響レビューを自動生成する」旨の説明、「セーブする」ボタン（承認待ちや却下といった状態は存在しない）
3. **セーブポイント一覧**: 特定プロジェクトの過去セーブポイント履歴（バージョン番号・作成者・作成日時・変更件数）
4. **セーブポイント詳細**: 1件のセーブポイントの全情報（バージョン番号、作成者/作成日時、コメント、**AIレビュー（Markdown形式のテキストで、影響範囲・リスク・確認点を含む。参考情報として枠で囲んで表示）**、含まれる変更のファイル単位diffテーブル）
5. **セーブ完了**: セーブ直後の結果確認画面（記録されたバージョン番号、AIレビューの全文を表示。AIレビューが生成できなかった場合はその旨を表示）

### 4. 変更履歴（受動的なログ画面）
- 対象プロジェクトを選ぶセレクトボックス
- ステータスフィルタは「すべて／未セーブ／セーブ済み」の2状態のみ
- 検知した変更のタイムライン（プロジェクト名・検知日時・ステータスバッジ・ファイル単位のdiffテーブル）。**アクションボタンは一切無い**（レビュー・承認ボタンを作らないこと）

### 5. 監査ログ
- 全操作履歴のテーブル（日時・ユーザー・操作種別・対象プロジェクト・対象バージョン・結果）
- 時系列（新しい順）

### 6. ユーザー管理
- このシステムを使えるユーザーの一覧（メールアドレス・グローバルロール）
- ユーザー追加フォーム（メールアドレス＋ロール選択）、各行に削除ボタン
- ロール説明（所有者＝すべて操作可／保守担当＝所有者に近いがメンバー管理は不可／開発者＝編集可／閲覧者＝見るだけ）

## 共通UI要素

- 左サイドバー: ブランド名「SavePoint」＋ナビゲーション（ダッシュボード/台帳/セーブ管理/変更履歴/監査ログ/ユーザー管理、監査ログとユーザー管理はOwnerのみ表示）＋下部に接続中のGoogleアカウント表示
- ステータスバッジ（成功=グリーン、警告=イエロー、エラー=レッド、未セーブ=グレー）
- ボタン: プライマリ（グリーン塗りつぶし）／セカンダリ（白地に枠線）／危険操作（赤系、GASへのロールバック等）
- 権限に応じてボタンが無効化される（例: Viewer権限ではセーブ不可、Owner権限以外はユーザー管理不可）
- AIレビューの表示エリアは、通常のコンテンツと視覚的に区別できる枠・アイコン等をつけ、「参考情報であり承認ではない」ことが一目でわかるようにする

## デザインしてほしいもの

上記6画面のビジュアルデザイン一式。既存の実装はダークサイドバー＋グリーンアクセントの簡易的なCSSで作られていますが、非エンジニアの方が安心して使える、もう少し洗練されたビジュアルに引き上げたいと考えています。特に4番目の「セーブポイント詳細・完了画面のAIレビュー表示」は新しい要素なので、参考情報であることが伝わるデザインを重点的に考えてください。配色・タイポグラフィ・カード/テーブルのスタイル・アイコンの使い方について提案してください。
