# SavePoint UIデザイン依頼プロンプト（Claude Design用）

以下をそのままClaude Designに貼り付けて使用する想定のプロンプト。

---

## プロダクト概要

「SavePoint」は、Google Apps Script（GAS）を業務で使っている非エンジニア企業向けの変更管理システムです。Git/GitHubの知識がなくても、ブラウザだけでGASの変更履歴確認・過去状態への復元（ロールバック）・変更のレビュー承認・権限管理・監査ログ・台帳管理ができます。

**想定ユーザー**: 税理士法人・中小企業の管理部門・情報システム担当者など、GitやGitHubを扱えない、または扱いたくない非エンジニアの方。ITツールへの習熟度は高くない前提でデザインしてください。

## トーン・世界観

- 信頼感・堅実さを重視（会計・法務に近い業務で使われるため、派手さより「事故を起こさない安心感」を優先）
- ダーク配色の左サイドバー＋明るいコンテンツ領域という構成を基本方針として踏襲（社内の別ツールで見慣れている構成のため）
- サイドバー: ダーク背景（#14161b程度）、白系の文字
- アクセントカラー: グリーン系（#23b26d程度）。承認・成功・プライマリアクションに使用
- 警告色: 黄系（変更あり等）、エラー色: 赤系
- フォント: Inter等のヒューマニストサンセリフ＋日本語はゴシック系（Hiragino Sans / Yu Gothic等）
- 全体的にホワイトスペースを活かした、カード＋テーブルベースのシンプルな管理画面デザイン

## 画面構成（4系統・実装済みの機能に対応）

### 1. ダッシュボード（トップ画面）
- サマリーカード4枚: GAS Projects数／変更あり／変更なし／認証エラー数
- 承認待ちリリース一覧（プロジェクト名・申請者・申請日時・変更量、承認/却下ボタン）
- 登録済みGASプロジェクトのカード一覧（プロジェクト名・Script ID・状態バッジ[確認中/変更あり/変更なし/認証エラー]・最終保存日時・「差分を見る」「セーブポイント」「リリース申請」ボタン、差分は展開表示）

### 2. 台帳（GASプロジェクトの管理画面）
- スタンドアロンGAS自動検出セクション（検出実行ボタン→検出結果リスト→ワンクリック登録）
- バインドGAS向け手動登録フォーム（Project Name/Script ID/Google Account/用途/担当部署/ステータス）
- プロジェクト一覧テーブル（Project Name/Script ID/用途/担当部署/ステータス/README（AI生成、展開表示）/メンバー管理（展開でメンバー一覧・追加・削除、ロールはowner/maintainer/developer/viewerの4段階）/編集ボタン）
- 各行はインライン編集可能（編集→保存/キャンセル）

### 3. リリース管理（5画面構成、Git PRに近いレビューフロー）
1. **プロジェクト選択**: 対象GASプロジェクトを選ぶ入口画面
2. **新規リリース作成**: 未リリースの変更を自動検出して表示（ファイル単位の追加/削除行数）、申請コメント入力欄、申請ボタン
3. **リリース一覧**: 特定プロジェクトの申請履歴（ステータスバッジ: 承認待ち/承認済み/却下、申請者、日時、変更量）
4. **リリース詳細**: 1件の申請の全情報（ステータス、申請者/承認者情報、コメント、ファイル単位の差分テーブル）、承認待ちなら承認/却下ボタン
5. **リリースサマリー**: 承認/却下後の結果確認画面（記録されたバージョン番号を表示）

### 4. 監査ログ
- 全操作履歴のテーブル（日時・ユーザー・操作種別・対象プロジェクト・対象バージョン・結果）
- 時系列（新しい順）

## 共通UI要素

- 左サイドバー: ブランド名「SavePoint」＋ナビゲーション（ダッシュボード/台帳/リリース管理/監査ログ、監査ログは管理者のみ表示）＋下部に接続中のGoogleアカウント表示
- ステータスバッジ（成功=グリーン、警告=イエロー、エラー=レッド、承認待ち=イエロー）
- ボタン: プライマリ（グリーン塗りつぶし）／セカンダリ（白地に枠線）／危険操作（赤系）
- 権限に応じてボタンが無効化される（例: Viewer権限ではセーブポイント作成不可、Owner権限以外は承認不可）

## デザインしてほしいもの

上記4画面（ダッシュボード・台帳・リリース管理のうち代表として新規リリース作成とリリース一覧、監査ログ）のビジュアルデザイン一式。既存の実装はダークサイドバー＋グリーンアクセントの簡易的なCSSで作られていますが、非エンジニアの方が安心して使える、もう少し洗練されたビジュアルに引き上げたいと考えています。配色・タイポグラフィ・カード/テーブルのスタイル・アイコンの使い方について提案してください。
